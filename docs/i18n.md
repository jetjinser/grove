# Internationalization and bilingual content

Grove has no hidden locale model on trees or pages. This reference describes the
language primitives and the bilingual authoring facility built on top of them.
Document `lang`/`dir` and localized interface labels are also accessibility
requirements; see [Accessibility](accessibility.md) for the renderer shell and
the project checklist.  Page-level authoring is covered in
[Authoring](authoring.md).

## Language tags

Tags are structurally validated and normalized before matching, catalog
lookup, and output, without checking IANA registry membership: the
language and extension subtags are lowercased, scripts are title-cased, and
alphabetic regions are uppercased. Extensions and private-use subtags remain
in their proper positions and do not affect script-based text direction.
Chinese uses a script and drops the region: bare `zh` and `zh-CN`, `zh-SG`, or
`zh-MY` become `zh-Hans`; `zh-TW`, `zh-HK`, or `zh-MO` become `zh-Hant`.
These forms are accepted on input. A project's `#:reader-locale` (passed to
`make-site-project` or `make-forester-project`) supplies the default reader
for `@bilingual` and the built-in `@bi`, so pages do not repeat a language
code; `#:reader` still overrides it per block.

## What already exists

- A page's `@locale` metadata selects its document language and direction,
  and supplies the locale for interface messages and date labels. The
  renderers' `#:locale` is the site fallback for pages without `@locale`; for
  HTML it also supplies the document language and direction. An explicit
  `#:html-attributes` entry still wins.
- HTML's `#:default-locale` selects the `x-default` member of each translation
  group. If `#:locale` is absent, it can also supply `<html lang>` and `dir`,
  but does not choose the interface message catalog or date formatting locale.
  The shared `#:settings` value supplies default values for
  `#:default-locale` and `#:site-url`; its default locale also initializes
  `#:locale` unless that is set explicitly. Explicit renderer options override
  these defaults locally. This lets a project choose different values for
  rendered interface text and translation-group defaults when needed.
- HTML emits `og:locale` from the page's `@locale` or renderer `#:locale`, and
  emits `og:locale:alternate` for the other members of its translation group.
  An explicit BCP 47 region is preserved; language-only tags use Forester's
  stable Open Graph territory default. `#:default-locale` does not select the
  page's `og:locale`.
- The HTML renderer accepts `#:html-attributes`, so a project sets a document
  language with `'((lang . "zh-Hans"))` and one direction with `'((dir . "rtl"))`.
- Backmatter headings use the `backmatter-*` message keys in the renderer's
  catalog, shared by HTML, text, and Gemtext.
- A content style can attach arbitrary HTML attributes, including `lang` and
  `dir`, to any element (`make-html-attributes`), and can replace its tag
  (`make-html-tag`) from `(grove style html element)`.

Those seams are enough for a project to localize a site without framework
changes. The modules below add reusable pieces.

## Locales and messages

`(grove i18n)` provides `make-locale`, `locale-tag`, `locale-lang`, `locale-dir`,
and `locale-html-attributes`. A locale is a validated BCP 47-style tag with a
derived text direction. Direction follows the script subtag first, so `az-Arab`
and `ks-Arab` are `rtl` while `ku-Latn` is `ltr`; without a script it falls back
to the primary language (`rtl` for Arabic, Hebrew, Persian, Urdu, and related
languages). The string accessors return independent values, so editing one
does not change the locale. `make-message-catalog` maps locale tags to
symbol-keyed strings, and
`message` resolves a key through that locale's shorter prefixes (`zh-Hant-CN`
tries `zh-Hant`, then `zh`), then the catalog default locale, then the key name.
Catalog tags are validated and canonicalized at construction; aliases such as
`zh-CN` and `zh-Hans` cannot both define entries in one catalog. The generic
`zh` entry remains available as a shared fallback for Chinese variants.
This is the surface for built-in interface text such as navigation and feed
labels; document text is translated as content instead.

`canonical-caseless-key` from `(grove unicode)` returns a canonical caseless
comparison key: it normalizes to NFD, applies full Unicode case folding, and
composes to NFC. So `Straße` and `STRASSE`, or a composed accent and its
decomposed spelling, compare equal. Topic selectors use it, which makes `@tag`
and `@taxon` matching insensitive to case and normalization form while stored
IDs stay canonical.

## Bilingual content

`(forester i18n)` adds the `@lang`, `@bilingual`, and `@term` commands and
lowers them to ordinary, cacheable Content IR:

```
@bilingual{
  @lang["en"]{ The grove is a small forest. }
  @lang["zh-Hans"]{ 树林是一片小小的森林。 }
}
```

A bilingual block contains aligned groups; each group contains language lanes.
Lanes are grouped in source order, and a language that already appears in the
current group starts a new group. So `en zh en zh` becomes two pairs, while
`en zh fr` stays one three-lane group. Whitespace between lanes is ignored.

`@bilingual` defaults to **fold** mode: the reader's language stays visible and
the other languages fold into a `<details>` disclosure, so the reading flow
stays single, links in the reader lane remain usable, and the source is
available on demand. `#:reader` chooses the visible language by BCP 47 tag,
matched by prefix (`#:reader "en"`, or `"zh"` matching `zh-Hans`); without it the
last lane of each group is shown. `#:source-label` sets the disclosure label
(default: the folded language tags). Pass `#:mode 'parallel` for the original
side-by-side layout:

```
@bilingual[#:reader "en" #:source-label "原文"]{ … }   ; fold (default)
@bilingual[#:mode 'parallel]{ … }                       ; side by side
```

The Chinese aliases above canonicalize before matching, catalog lookup, and
output, so a page may use one without changing the rendered language tags.

Both modes lower to the same lane IR, so the choice is a presentation decision,
not a data one.

`@lang` decodes its body with the normal paragraph decoder, so prose, inline
commands, and nested content all work inside a lane. `@term["fr"]{une forêt}`
marks a short inline span with its own language.

Because commands are ordinary bindings, a project can define short aliases in a
shared module instead of repeating language tags:

```scheme
(define (en . body) (apply lang "en" body))
(define (zh . body) (apply lang "zh-Hans" body))
```

Then `@bilingual{ @en{...} @zh{...} }` reads as naturally as the content.
The [`examples/bilingual`](../examples/bilingual/project.scm) module re-exports
the long forms; add aliases the same way.

### Presentation

Lanes carry `lang` and `dir` properties and a content style, so the default HTML
renderer emits nested, language-tagged markup without any renderer change. Fold
mode adds a disclosure; parallel mode stays a grid of lanes:

```html
<!-- fold (default): the reader lane stays visible; sources are folded -->
<div class="bilingual" data-mode="fold">
  <div class="bilingual-pair">
    <div class="bilingual-lane" lang="en" dir="ltr"><p>...</p></div>
    <details class="bilingual-source">
      <summary><span class="bilingual-more">zh-Hans</span></summary>
      <div class="bilingual-lane" lang="zh-Hans" dir="ltr"><p>...</p></div>
    </details>
  </div>
</div>

<!-- parallel -->
<div class="bilingual">
  <div class="bilingual-pair">
    <div class="bilingual-lane" lang="en" dir="ltr"><p>...</p></div>
    <div class="bilingual-lane" lang="zh-Hans" dir="ltr"><p>...</p></div>
  </div>
</div>
```

In fold mode the reader's lane is itself the control: clicking it reveals the
other lanes, so there is no separate label. A trailing `.bilingual-more` hint
carries the folded language (and a chevron via CSS); pass `#:source-label` to
replace it with your own text.

`(forester style i18n)` ships a minimal, reset-style stylesheet and
`default-bilingual-style`. Compose it with the standard Forester style:

```scheme
(compose-html-styles default-html-style default-bilingual-style my-style)
```

The default stylesheet only keeps the markup readable: a `grid` for parallel
pairs (which stacks on narrow viewports), a single column for `data-mode="fold"`,
a pointer cursor on the reader lane, a chevron on the `.bilingual-more` hint, and
a hover/focus background. Visual design — rules, spacing, script-aware line
height, foreign-term treatment — belongs to project styles.

Set the document language and direction from a locale with
`locale-html-attributes`, for example `#:html-attributes (locale-html-attributes
(make-locale "en"))`; see the example project.

### Text output

`content->text` preserves lane order and stacks them. The built-in text and
Gemtext renderers mark each lane by default, so `grove build` output is labelled
without any configuration:

```
[en] The grove is a small forest.
[zh-Hans] 树林是一片小小的森林。
```

The built-in text and gemtext renderers compose `bilingual-text-rules` from
`(forester i18n)` with project rules, so custom rules can override a lane's
text or call `(next)` to preserve the bilingual labels. A standalone text
renderer can pass the same rules value to `(grove render text)`.

## Formatting

`format-date`, `format-number`, and `plural` provide locale-sensitive formatting
for values that would otherwise be hard-coded. Dates take a valid Gregorian
`YYYY-MM-DD` string and a `#:style` of `short`, `medium` (default), or `long`;
invalid dates pass through unchanged, while an unknown style is an argument
error. `iso-date?` exposes the same calendar-date check to metadata readers and
other project code. Numbers use locale-specific grouping
when the mapped system locale is available and comma-separated groups of three
otherwise. `plural` accepts an integer count and a unique alist of string
forms keyed by the CLDR categories `zero`, `one`, `two`, `few`, `many`, and
`other`; the caller formats the selected string.

```scheme
(format-date "zh-Hans" "2026-09-27")            ; "2026年9月27日"
(format-date "en" "2026-09-27" #:style 'long)   ; "September 27, 2026"
(format-number "en" 1234567)                    ; "1,234,567"
(plural "en" 2 '((one . "~a item") (other . "~a items"))) ; "~a items"
```

The built-in date data covers `en`, `zh-Hans`, `de`, and `fr`; other locales
return the ISO date. `plural` implements the `en` one/other distinction, the
single Chinese form, the Russian and Polish one/few/many rules, and the Arabic
zero/one/two/few/many categories. Other languages fall back to one/other by
count. Add a locale table before promising localized output for another
language.

Number grouping uses Guile's `(ice-9 i18n)` formatter and installed system
locale data; unsupported locales use comma grouping.

## Locale routes and alternates

A page declares its language and translation group as metadata:

```
@locale["zh-Hans"]
@translation["intro"]
```

`locale-page-path` turns a page-id to locale mapping into a page-path
procedure. The default keeps Forester's flat layout and appends the locale
suffix, leaving the default locale and unlocalized pages unprefixed:

```scheme
(make-html-routes
  #:home-page "home"
  #:page-path (locale-page-path locale-of #:default-locale "en"))
;; guide.html, guide-zh.zh-Hans.html
```

Route callbacks receive independent page-ID strings, and route procedures
return independent path strings. A callback can build paths with ordinary
mutable Scheme strings without exposing those values through the routes API.
Keep `locale-of` and any path builder deterministic for a fixed site: renderers
may evaluate them repeatedly while resolving routes and cache identity.

Pass a path builder for another layout, such as a locale directory:

```scheme
(make-html-routes
  #:home-page "home"
  #:page-path (locale-page-path
                locale-of
                (lambda (locale id)
                  (if locale
                      (string-append locale "/" id ".html")
                      (string-append id ".html")))
                #:default-locale "en"))
```

Translation groups emit `<link rel="alternate">` for every member and
`x-default` for the default locale by default; `#:hreflang? #f` disables them.
A named language switcher with the current language marked is on by default for
groups of two or more pages; `#:language-switcher? #f` disables it. The sitemap
renderer emits the same alternates as `xhtml:link` when given
`#:default-locale`.

`derive-translation-groups` from `(forester render context)` returns an ordered
association list of `(translation-key . pages)` from a page list. It keeps the
first-occurrence order of group keys and the original page order within each
group. `make-site-render-context` derives this data by default; pass
`#:translation-groups` to replace or omit it when a custom renderer needs a
different grouping, order, or no groups.

The configured home page keeps `index.html`; a separate home page for another
locale uses the locale suffix (`home.zh-Hans.html`).

Pass one `make-site-settings` value to the HTML, sitemap, and RSS renderers
to keep the site origin and default locale aligned across canonical links, feed
locations, alternate links, and the HTML interface language. A
renderer-specific value overrides the shared setting:

```scheme
(define settings
  (make-site-settings #:site-url "https://example.org"
                      #:default-locale "en"))

(make-site-project
  #:renderers
  (list (make-html-renderer
          #:options (make-html-options #:settings settings ...))
        (make-sitemap-renderer #:settings settings ...)
        (make-rss-renderer #:settings settings ...)))
```

## Sorting and collation

`sort-strings` stably sorts strings by `canonical-caseless-key` from
`(grove unicode)`. Without options, ordering is by code point on that key:
deterministic everywhere, but not language-tailored.

Pass `#:locale` to use the platform's locale collation data when it is
available:

```scheme
(sort-strings topics #:locale "fr")   ; éclair before Zebra
(sort-strings topics #:locale "de")   ; Äpfel before Zebra
(sort-strings topics #:locale "zh")   ; 阿 before 波 (pinyin)
```

The comparator folds case first (so `Straße` and `STRASSE` tie), then uses
glibc's ISO 14651 tables through `(ice-9 i18n)`. Grove maps supported language
tags to system locales internally; unsupported tags, or a system without the
locale data, fall back to folded code-point order. Use
`locale-collation-comparator` when a Scheme sorting operation needs the same
locale-aware comparison directly. Pass `#:compare` to `sort-strings` to take
over completely.

**Scope.** This is best-effort collation, not UCA/CLDR conformance: it depends
on the installed locale data (the manifest ships `glibc-locales`), and
language-specific rules such as German phonebook order, Swedish `å/ä/ö`, or
`ß`/`ss` equivalence are not guaranteed. The result is deterministic for a
fixed environment, but may change with a different glibc or locale set. Use
`#:compare` when exact ordering matters.
