# Internationalization and bilingual content

Grove has no hidden locale model on trees or pages. This reference describes the
language primitives and the bilingual authoring facility built on top of them.
Document `lang`/`dir` and localized chrome labels are also accessibility
requirements; see [Accessibility](accessibility.md) for the renderer shell and
the project checklist.

## What already exists

- The HTML renderer accepts `#:html-attributes`, so a project sets a document
  language with `'((lang . "zh-CN"))` and one direction with `'((dir . "rtl"))`.
- Backmatter headings are configurable through `#:backmatter-labels` on the
  HTML, text, and Gemtext renderers.
- A content style can attach arbitrary HTML attributes, including `lang` and
  `dir`, to any element (`make-html-attributes`), and can replace its tag
  (`make-html-tag`).

Those seams are enough for a project to localize a site without framework
changes. The modules below add reusable pieces.

## Locales and messages

`(grove i18n)` provides `make-locale`, `locale-tag`, `locale-lang`, `locale-dir`,
and `locale-html-attributes`. A locale is a validated BCP 47-style tag with a
derived text direction. Direction follows the script subtag first, so `az-Arab`
and `ks-Arab` are `rtl` while `ku-Latn` is `ltr`; without a script it falls back
to the primary language (`rtl` for Arabic, Hebrew, Persian, Urdu, and related
languages). `make-message-catalog` maps locale tags to symbol-keyed strings, and
`message` resolves a key through that locale's shorter prefixes (`zh-Hant-CN`
tries `zh-Hant`, then `zh`), then the catalog default locale, then the key name.
This is the surface for chrome strings such as navigation and feed labels;
document text is translated as content instead.

`match-key` returns a canonical caseless comparison key: it normalizes to NFD,
applies full Unicode case folding, and composes to NFC. So `Straße` and
`STRASSE`, or a composed accent and its decomposed spelling, compare equal.
Topic selectors use it, which makes `@tag` and `@taxon` matching insensitive to
case and normalization form while the stored IDs stay canonical.

## Bilingual content

`(forester i18n)` adds the `@lang`, `@bilingual`, and `@term` commands and
lowers them to ordinary, cacheable Content IR:

```
@bilingual{
  @lang["en"]{ The grove is a small forest. }
  @lang["zh-CN"]{ 树林是一片小小的森林。 }
}
```

A bilingual block contains aligned groups; each group contains language lanes.
Lanes are grouped in source order, and a language that already appears in the
current group starts a new group. So `en zh en zh` becomes two pairs, while
`en zh fr` stays one three-lane group. Whitespace between lanes is ignored.

`@bilingual` defaults to **fold** mode: readers see one language and the other
languages fold into a `<details>` disclosure, so the reading flow stays single
and the source is available on demand. `#:reader` chooses the visible language
by BCP 47 tag, matched by prefix (`#:reader "en"`, or `"zh"` matching `zh-CN`);
without it the last lane of each group is shown. `#:source-label` sets the
disclosure label (default `source`). Pass `#:mode 'parallel` for the original
side-by-side layout:

```
@bilingual[#:reader "en" #:source-label "原文"]{ … }   ; fold (default)
@bilingual[#:mode 'parallel]{ … }                       ; side by side
```

Both modes lower to the same lane IR, so the choice is a presentation decision,
not a data one.

`@lang` decodes its body with the normal paragraph decoder, so prose, inline
commands, and nested content all work inside a lane. `@term["fr"]{une forêt}`
marks a short inline span with its own language.

Because commands are ordinary bindings, a project can define short aliases in a
shared module instead of repeating language tags:

```scheme
(define (en . body) (apply lang "en" body))
(define (zh . body) (apply lang "zh-CN" body))
```

Then `@bilingual{ @en{...} @zh{...} }` reads as naturally as the content.
The [`examples/bilingual`](../examples/bilingual/project.scm) module re-exports
the long forms; add aliases the same way.

### Presentation

Lanes carry `lang` and `dir` properties and a content style, so the default HTML
renderer emits nested, language-tagged markup without any renderer change. Fold
mode adds a disclosure; parallel mode stays a grid of lanes:

```html
<!-- fold (default): the reader lane is the disclosure control -->
<div class="bilingual" data-mode="fold">
  <details class="bilingual-pair">
    <summary class="bilingual-lane" lang="en" dir="ltr">
      <p>...</p>
      <span class="bilingual-more">zh-CN</span>
    </summary>
    <div class="bilingual-lane" lang="zh-CN" dir="ltr"><p>...</p></div>
  </details>
</div>

<!-- parallel -->
<div class="bilingual">
  <div class="bilingual-pair">
    <div class="bilingual-lane" lang="en" dir="ltr"><p>...</p></div>
    <div class="bilingual-lane" lang="zh-CN" dir="ltr"><p>...</p></div>
  </div>
</div>
```

In fold mode the reader's lane is itself the control: clicking it reveals the
other lanes, so there is no separate label. A trailing `.bilingual-more` hint
carries the folded language (and a chevron via CSS); pass `#:source-label` to
replace it with your own text.

`(forester style i18n)` ships a minimal, reset-style stylesheet and
`default-bilingual-style`. Compose it with the standard Forester style:

```scheme
(compose-html-styles default-html-style default-bilingual-style my-style)
```

The default stylesheet only keeps the markup readable: a `grid` for parallel
pairs (which stacks on narrow viewports), a single column for `data-mode="fold"`,
a pointer cursor on the reader lane, a chevron on the `.bilingual-more` hint, and
a hover/focus background. Visual design — rules, spacing, script-aware line
height, foreign-term treatment — belongs to project styles.

Set the document language and direction from a locale with
`locale-html-attributes`, for example `#:html-attributes (locale-html-attributes
(make-locale "en"))`; see the example project.

### Text output

`content->text` preserves lane order and stacks them. The built-in text and
Gemtext renderers mark each lane by default, so `grove build` output is labelled
without any configuration:

```
[en] The grove is a small forest.
[zh-CN] 树林是一片小小的森林。
```

`bilingual-text-handlers` remains available when calling `content->text`
directly or from a custom renderer, and the terminal and SSH browser use it too.

## Not yet covered

- Locale-prefixed routes, `hreflang` alternates, and a language switcher for
  fully localized sites with parallel source trees.
- Locale-aware date, number, and plural formatting.
- Locale-aware collation (sorting) for topic lists; matching uses canonical
  caseless keys, but ordering stays by code point.
